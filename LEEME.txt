Redespliega:
- supabase/functions/invite-program-staff/index.ts

Nombre:
invite-program-staff

Verify JWT:
OFF

Qué cambia:
- Busca primero si el email ya existe en Supabase Auth.
- Si el usuario ya está CONFIRMADO:
  no lo elimina ni intenta Invite user otra vez;
  la asignación queda Pendiente para aceptar desde Scan.
- Si existe un usuario NO confirmado y con invited_at:
  se considera una invitación anterior atascada;
  se elimina ese usuario Auth no confirmado y se vuelve a ejecutar inviteUserByEmail().
- El panel muestra confirmation_sent_at cuando Supabase confirma el envío.
- Los errores de Invite user ahora aparecen explícitamente.

PRUEBA:
1. Usa un correo completamente nuevo que nunca haya estado en Authentication -> Users.
2. Agrégalo como empleado.
3. Debe mostrar "Invitación enviada" y fecha/hora.
4. Revisa Authentication -> Users:
   el nuevo usuario debe tener invited_at / confirmation_sent_at.
5. Si no llega al buzón aunque confirmation_sent_at exista:
   el problema ya es de entrega SMTP/spam, no de la función.

IMPORTANTE:
Supabase requiere Custom SMTP para enviar Auth emails a destinatarios arbitrarios en producción.
Si tus OTP sí llegan a correos externos, probablemente ya lo tienes configurado.
